# JavaScript-only patches that a GAIUS_TEAVM_TARGET=wasmgc overlay build skips: their
# PatchRegistry spec names only the js target ("<KIND> js"), and the registry prints
# "PATCH_TARGET_SKIPPED <patchId> target=wasmgc" (patchkit lint checks this list against the
# specs).
# check-build-log-skips.mjs (G4) requires a wasmgc build log to skip exactly the
# ids listed here for its profile, so a semantic patch cannot disappear from the
# WebAssembly GC build by being marked js-only, and a JavaScript accelerator
# cannot reach it by losing the mark.  Each one must leave vanilla bytecode that
# is exact on wasm (i64 and f32 are native there, casts saturate), or exist only for
# the coroutine contract of the one-thread JavaScript build (yields, synchronous
# worldgen steps, packet slicing): the wasm build runs every Java thread as a JSPI
# activation that parks while it waits, so the vanilla code runs there
# (classification.tsv: REQUIRED, wasm js-only).
#
# <patchId> | <profiles: * or the profile terms of the spec> | <reason>
